# 正式初始化由 Launch 统一编排

架构创建需要保持同步、可回滚且不依赖运行时资源，因此模块的 `OnInitialize` 只建立纯内存状态和依赖，正式资源初始化由 Launch 按依赖关系统一编排。集中编排让启动呈现、进度、取消和失败收束共享同一生命周期，也避免任意模块通过同步 Ensure 或 `WaitForCompletion` 隐式阻塞主线程。

## 备选方案

- 由各模块在 `OnInitialize` 中自行加载资源：启动顺序、失败回滚和呈现交接会分散到多个所有者。
- 在使用点同步 Ensure：调用点看似简单，但会隐藏未就绪状态并引入不可控的主线程等待。

## 影响

需要运行时资源的模块必须公开可取消的异步初始化入口，并在未就绪时返回明确状态或异常。Launch 负责表达依赖和进度，模块仍负责自身 operation 的持有、回滚与释放；当前契约见 [初始化流程](../Architecture/Initialization.md)。
