# 存档读取与运行时恢复分离

存档文件读取可能失败或被取消，且活动 Entity 与长期角色状态之间存在生命周期约束，因此 Load 只读取、反序列化并校验独立 DTO，不修改运行时状态。恢复通过重新进入 GameProcedure，在没有活动 Entity 后建立默认角色状态、应用存档数据并加载目标场景，从明确的流程边界重建运行时实例。

## 备选方案

- Load 成功后直接修改当前 Model 和活动 Entity：可以减少一次流程切换，但部分提交、旧场景引用和恢复顺序会形成难以回滚的中间状态。
- 将恢复行为放入存档 DTO：会让传输格式依赖运行时模块和生命周期，削弱格式校验与迁移边界。

## 影响

预读失败不会切换流程或修改 Model；恢复前必须清理活动 Entity。代价是成功读档需要重新进入流程并重建场景对象，但提交边界、失败语义和资源所有权保持明确。
