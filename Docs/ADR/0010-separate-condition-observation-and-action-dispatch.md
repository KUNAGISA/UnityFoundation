# 行为同步 FIFO 分发，发起即视为成功

配表行为可能在修改状态或反馈结果时重入提交另一行为，直接嵌套执行会中断当前行为的同步逻辑。决定由 ActionSystem 集中分发，以同步 FIFO 保证当前行为及其结果回调完成后再执行后续提交；成功表示行为已发起，持续行为的驱动、独占替换和取消归所属系统，不引入跨帧请求或执行监视器。

当前接口与失败语义见 [ActionSystem](../Architecture/Actions.md)。条件观察的取舍见 [ADR-0025](0025-declarative-condition-sources-and-batched-observation.md)，场景事件是否可以再次触发由业务条件表达，见 [ADR-0022](0022-condition-driven-scene-event-availability.md)。

## 备选方案

- 单一 RuleSystem 同时提供条件观察与行为分发：入口较少，但条件观察的生命周期与行为同步重入的协调职责不同，选择分别维护。
- 允许同步嵌套执行：无需队列，但每个 Action 都要考虑在状态修改到一半时被其他 Action 改写前提或销毁来源。
- 排队并等待持续行为完成：可以避免剧情替换，但行为契约是发起即成功，独占冲突由所属系统处理；不把长期生命周期带入分发入口。
- 出队重新检查触发条件：能跳过已经失效的事件，但会改变已触发行为的决定；选择提交前完成业务判断，队列只调整同步执行顺序。

## 影响

- 队列不提供状态事务，也不回滚已发起的持续行为；后续失败或取消不会改变已经反馈的发起结果。
- 多个剧情 Action 连续发起时，后者按 SequenceSystem 的独占规则替换前者，不等待前一段剧情完成。
- 结果回调可能在 Submit 返回前同步发生，也可能因重入排队而延后。不可通过条件观察 Token 取消的分发回调，由消费方保护登记身份，避免修改重建后的业务状态。

## 后续简化（2026-11-01）

移除场景事件的临时提交标记后，已没有消费方需要结果回调，因此删除 ActionSystem 的结果反馈机制，提交入口简化为 `void Submit(int actionId)`。Resolver 的 bool 仅用于失败日志；同步 FIFO、单轮循环保护及持续行为归所属系统管理的决定保持有效。超限与 Shutdown 直接清空未执行项，以上关于结果回调及其登记保护的描述仅记录原方案背景。
