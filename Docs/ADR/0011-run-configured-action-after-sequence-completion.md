# 剧情正常结束后执行可选配表行为

策划约定剧情过程中的效果主要通过脚本指令表达，但仍需要统一的正常结束行为入口。决定在演出表中增加可空的行为总表引用，由 SequenceSystem 在剧情自然完成并释放旧播放后提交，以便各脚本分支共享收尾配置，同时支持结束行为启动下一段剧情。

当前字段与生命周期见 [配表与生成代码](../Architecture/Tables.md) 和 [Sequence 框架](../Architecture/Sequence.md)。行为发起成功与剧情播放完成仍是两个时点，沿用 [ADR-0010](0010-separate-condition-observation-and-action-dispatch.md) 的分发语义。

## 备选方案

- 在脚本每个结束分支显式执行收尾行为：脚本可以表达过程效果，但重复配置收尾容易遗漏，选择由演出表提供统一入口。
- 使用播放行为的发起成功回调执行：该回调不等待剧情结束，不能代表自然完成。
- 在统一清理路径执行：取消、替换和异常也会进入清理，可能错误触发正常结束效果。
- 要求所有剧情填写行为 ID：无结束效果的剧情需要额外配置空操作，选择可空引用兼容现有剧情。

## 影响

- 仅正常完成的本次播放提交一次；取消、离场、重载和失败不提交。重复播放并正常完成会再次提交，跨播放去重由业务负责。
- 旧播放先释放、状态先确认为成功，再提交结束行为；行为失败不会回滚剧情完成结果，也不等待持续行为结束。
