# 将剧情脚本加载与编译缓存交给独立对象

SequenceSystem 同时处理播放编排、三条脚本准备路径和 Lua 编译缓存，使播放生命周期与资源细节交织。决定由其持有普通对象 SequenceScriptCache，集中脚本加载、共享预加载和编译引用管理，并直接返回 Lua 协程；System 保留播放编排，文本和立绘继续由现有所有者管理。

当前职责、接口和所有权交接见 [Sequence 框架](../Architecture/Sequence.md)。

## 备选方案

- 继续把缓存字典和加载分支留在 System：无需新增类型，但播放入口仍需理解缓存状态、共享等待和资源释放。
- 新增全局资源管理模块：Lua 编译引用依附具体主状态，与 Unity 资源 operation 的生命周期不同，没有跨系统共享需求，选择由 System 局部持有对象。
- 用 PreparedScript 包装准备结果并延后创建协程：可统一承接源资源和缓存引用，但增加一层准备结果及释放约定，选择直接返回协程并由 System 立即接管。

## 影响

- 缓存保存 Lua 编译函数引用，借用主状态；关闭顺序保持先停止播放、释放缓存，再关闭主状态。直接返回的协程在等待文本期间也由播放收尾管理。
- 保留仅显式预加载才缓存的策略。调用方取消只终止自身等待，缓存作用域管理共享加载；失败条目允许重试。
- 遵循现有主线程和异步取消契约，不为假设的后台执行增加线程切换或重复检查同一令牌；独立的缓存生命周期、代次和播放身份校验继续保留。
