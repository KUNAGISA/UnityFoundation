# 保留剧情播放所有权并复用独立 ADV 状态

ADV 状态的组织方式由 [ADR-0019](0019-split-adv-sessions-and-widgets-with-action-driven-dialogue.md) 调整；单次播放资源仍由 SequenceSystem 完整持有，对白继续通过 Action 参与调度。

SequenceSystem 的播放资源没有独立于当前播放的使用者，而 AdvSession 同时承载对白、选项和立绘状态，使动作与 View 容易跨越职责边界。决定由 SequenceSystem 保留单次播放资源的完整所有权，AdvSession 持有并在整段剧情中复用普通对象 AdvDialogue 与 AdvPortraitRegistry，分别集中对白状态和立绘修改。这样将确有独立规则的状态从会话编排中分离，同时避免仅为搬移私有方法而新增播放所有者或架构模块。

当前接口、调度时点、资源交接与清理契约见 [Sequence 框架](../Architecture/Sequence.md)。本决策延续脚本缓存由局部对象管理的边界，不改变缓存与播放各自的所有权。

## 备选方案

- 将单次播放资源抽成 SequenceOperation：可以缩短 System，但该对象没有独立的调用方或生命周期，System 仍需协调加载、输入、文本和结束行为，增加一层所有权交接而没有减少调用方需要理解的状态。
- 将全部对白规则留在 AdvSession 或分散到 Action 与 View：不新增对象，但对白身份、计时、语言更新和测量反馈容易由多个位置共同维护，选项与对白通知也会相互耦合。
- 将对白注册为架构 Model，或每条对白单独创建状态对象：前者扩大了局部状态的访问范围与生命周期，后者增加频繁对话的分配；选择随 AdvSession 复用普通对象，无需对象池。

## 影响

- 对白仍由 Action 驱动计时，不新增帧调度入口。Session 负责本地化解析与输入编排，View 负责表现和 TMP 测量；对白身份与内容修订共同阻止旧动作或旧测量修改新内容。
- 立绘修改、通道覆盖和通知统一经过 Registry，外部只读状态。即时设置与延迟启动的持续动作保留不同语义，动作启动时读取起点。
- Lua 主状态、缓存和单次播放资源仍由 System 持有；协程创建后到 Player 绑定前也必须存活，原始协程指针交接继续使用现有 Lua API 的强引用与关闭约定，不新增资源包装类型。
- 清理信任既有不抛异常契约，保留真实异步失败和旧任务身份校验；正常结束行为在旧资源释放、播放确认成功后提交，取消不触发结束行为。
