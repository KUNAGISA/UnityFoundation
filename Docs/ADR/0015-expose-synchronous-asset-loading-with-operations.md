# 同步资源加载作为服务接口并保留 operation 所有权

配表、Entity、UI 和资源作用域都存在同步读取需求，原先由各调用方组合异步加载与同步等待。决定将单资源和按 Label 批量同步加载纳入 `IAssetService` 正式接口，由后端实现，并继续返回与异步加载相同类型的 operation；这样可为 Addressables、YooAsset 等后端保留各自的同步加载策略，同时统一资源持有、结果状态与释放责任。

当前接口、初始化要求、生命周期和后端限制见 [IAssetService](../Architecture/AssetService.md)。

## 备选方案

- 通过扩展方法统一组合异步加载与等待：当前 Addressables 和 YooAsset 的资源加载都能支持这种组合，但会将同步策略固定在服务实现之外；选择让后端兑现同步契约，实现内部仍可复用异步入口。
- 同步接口只返回资源对象：调用更短，但会丢失用于持有和释放资源的 operation，迫使调用方另建所有权协议；选择沿用现有 operation。

## 影响

- 保留 operation 的 `WaitForComplete()`，供已缓存但尚未完成的加载同步收束，避免重新发起请求。
- 同步只改变完成时机，不改变初始化要求、加载失败表达和释放责任；等待抛异常时，后端释放尚未交付的 operation，再传播异常。
- 同步支持受后端、平台和资源可用条件限制，可能阻塞主线程；场景继续异步加载与激活，不承诺完整同步加载。本次仅实现 Addressables 后端。
