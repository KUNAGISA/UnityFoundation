# 信任已验证契约并将防御保留在真实边界

正式启动与场景预览均由 Launch 等待全局准备完成，Procedure 参数、输入通道和资源 operation 也各有明确的入口与生命周期契约。决定让契约的建立者负责校验，受该契约覆盖的调用链直接使用已保证的依赖，并删除没有读取者的加载状态与重复判断，避免把调用错误掩盖为静默跳过或空结果。初始化期间的帧驱动、异步任务替换、取消、部分失败清理及外部资源输入仍是实际可达边界，继续保留对应保护。

当前启动约束、参数入口与资源返回语义分别见[初始化流程](../Architecture/Initialization.md)、[Procedure 流程](../Architecture/Procedure.md)和 [IAssetService](../Architecture/AssetService.md)。

## 备选方案

- 各调用点重复判断就绪、参数和依赖：可以局部避免异常，但增加无消费者状态及重复分支，也会让违反契约的调用看似成功。
- 统一移除初始化与清理检查：改动简单，但无法覆盖异步初始化期间的 Tick、旧任务回写和只创建部分资源后的回滚。

## 影响

- 新增独立入口或资源后端时，需要重新核对并兑现现有契约；异步资源加载正常返回非空 operation，资源失败仍通过 operation 或异常表达。
- 初始化状态是否保留取决于真实读取者；`LocalizationSystem.IsInitialized` 等仍参与幂等、未就绪检查或生命周期决策的状态继续保留。
- 减少内部判断依赖正确的生命周期所有权，不能据此删除初始化失败时的释放、资源结果检查或异步身份校验。
