# 全局设置修改与显式保存分离

语言切换时立即写文件适合单一低频设置，但扩展音量等连续调整后，会让每次内存修改都承担同步文件 IO。决定由 `GlobalSettingModel` 在值变化时更新内存并标脏，通过 `SaveIfDirty()` 显式合并保存，由调用流程选择保存时机，目前在 GM 命令成功后和架构正常关闭时执行。保留同步原子写入与现有模块生命周期，不增加自动保存 System 或延迟任务。

该决定调整 [ADR-0017](0017-synchronous-language-switch-command.md) 中先保存再重载的持久化时机，保留同步语言切换和 Command 编排。现行接口与关闭约束见 [Sequence 框架](../Architecture/Sequence.md)。

## 备选方案

- Setter 每次立即保存：调用方简单，但连续调整会重复写入，也会让写入失败阻止设置在内存中生效。
- System 统一延迟保存：可以自动合并修改，但增加调度、取消和关闭收束；当前保存入口明确，暂不需要这层生命周期。
- 仅在退出时保存：写入次数少，但正常运行期间没有提交点，异常终止时丢失修改的范围更大。

## 影响

- 调用方需要在业务提交点显式保存；后续设置界面等入口复用同一接口，不能依赖 Setter 自动落盘。
- 初始化和读取不标脏，文件缺失或内容无效时保留默认回退，不自动覆盖原文件。只有写入成功才清除脏标记，失败可以重试。
- 文本重载失败不回滚内存语言，GM 不继续保存；关闭时仍会尝试保存待提交设置。关闭保存失败由已有架构异常处理记录，Model 仍释放引用，其余模块继续清理。
- 正常关闭补存发生在存储服务释放前；强制终止无法保证执行关闭回调，尚未显式保存的修改可能丢失。
