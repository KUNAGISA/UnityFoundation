# 场景事件由业务条件控制，不记录执行历史

行为发起成功与剧情正常完成是不同的时点，场景事件自身记录完成历史会把业务进度与触发机制绑定。决定移除事件完成记录和 repeatMode，以条件及业务变量表达是否还能触发，剧情正常完成后的效果继续由结束行为提交。提交期间的临时防重入只作用于提交入口，对外可触发状态、Collider 和表现对象始终由条件结果决定。

本决定调整 [ADR-0010](0010-separate-condition-observation-and-action-dispatch.md) 中场景事件成功发起即记完成的策略，保留其同步分发与登记版本检查；剧情结束行为继续遵循 [ADR-0011](0011-run-configured-action-after-sequence-completion.md)。现行职责见[配表与生成代码](../Architecture/Tables.md)。

## 备选方案

- 保留一次性／可重复枚举和完成历史：触发器可以自行决定重复，但与变量条件形成两套业务状态，并把剧情发起当作完成。
- 用提交防重入状态临时关闭 Collider：提交完成重新启用 Collider 会让仍在区域内的玩家再次产生 Enter，可能连续发起剧情。
- Collider 常开并在触发器中增加逻辑开关：可以阻断上述循环，但条件恢复时区域内玩家必须实际离开再进入，改变原有条件驱动的触发行为。
- 将防重入锁延长到剧情结束：需要事件系统持有持续行为生命周期，偏离行为发起即成功的约定。

## 影响

- 需要防止再次触发的内容必须在业务行为中更新变量。取消、替换或失败不提交正常结束行为，因此不会自动完成业务条件。
- 条件持续成立时，提交和完成不会切换 Collider；真实离开再进入仍可触发。条件恢复时重新启用 Collider，区域内玩家可以再次触发。
- 仍保留提交期间的临时防重入和登记版本检查，防止同步重入及旧场景回调修改新登记；它们不构成业务执行历史。
