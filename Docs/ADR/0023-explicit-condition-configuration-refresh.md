# 条件配置刷新由 GM 显式发起

当前已移除观察缓存和显式条件刷新，后续求值直接读取最新配置，消费状态由分帧轮询更新，见 [ADR-0024](0024-consumer-owned-condition-polling.md)。下文保留历史决定。

变量默认值通过 Query 读取最新配置，开发期配表重载无需修改 Model，也不应让 ConditionSystem 承担变量同步或表监听工作。决定由 ConditionSystem 只订阅运行时依赖变化；配置变更后的观察缓存和依赖重建通过 condition.refresh GM 显式发起，沿用现有批次缓存提交与 FIFO 通知机制。

本决定调整 [ADR-0010](0010-separate-condition-observation-and-action-dispatch.md) 中配表重载自动全刷的策略。现行接口及调用约束见 [ConditionSystem](../Architecture/Conditions.md)。

## 备选方案

- 监听条件总表及变量表重载并自动刷新：开发时即时生效，但会将开发期表监听职责和订阅生命周期带入条件求值系统。
- 重载后清空变量或重新填充默认值：会改动运行时覆盖记录，也与按需读取默认值的选择冲突。
- 为全量刷新增加 Command、排队标记或合并机制：当前只有主线程 GM 外部入口，直接调用即可，不扩大重入契约。

## 影响

- 即时 Query 和强制即时条件求值读取最新配置；已观察条件的缓存与依赖不会因配置重载自动更新，开发者需显式刷新。
- 全量刷新只处理已观察条件，保留观察 Token 和计数，先提交本轮缓存再发布结果变化；结果不变不通知。
- 不支持从条件通知回调重入全量刷新。通知引起的运行时按类型刷新仍进入 FIFO，并在本轮通知结束后处理。
