# 声明式条件来源与 LateTick 批量观察

分帧轮询降低条件扩展成本，但关键剧情与 NPC 配置更新没有固定检查时机。决定保留人工定义的数据源分类和已有业务事件映射，用专用 ConditionResolverAttribute 声明来源并生成完整依赖收集；ConditionSystem 集中观察，在 LateTick 合并求值，消费方按批次应用变化。条件观察继续保留即时求值和条件控制业务可用性的契约，Action 分发继续采用同步 FIFO。

Action 和 Condition 使用独立菜单、专用收集与校验，只复用底层模板/文件工具。观察以 Token 归属于业务状态，闭包仅在登记时创建，不要求消费方另建登记 ID 映射表。当前接口与扩展规则见 [ConditionSystem](../Architecture/Conditions.md) 和[生成流程](../Architecture/DefinitionGeneration.md)。

条件观察取消后不再派发旧通知，消费方信任该契约；同步 NPC 刷新不额外维护版本。ConditionSystem 信任刷新期间不发生 Shutdown 的架构生命周期约定，不维护关闭版本。SceneEvent 仅在状态接收方和可重入 Action 分发边界保留版本保护，避免旧遍历或不可取消的分发回调操作重建后的登记。运行时 CollectSources 遇到未支持的条件类型只记录 Error 并返回 None，避免单个缺失分支通过异常中断其余来源收集；生成期的声明及定义覆盖校验仍然保留。

## 备选方案

- 保留分帧轮询：无需通知覆盖契约，但响应时间取决于游标和预算。
- 自动以事件类型作为分类并生成订阅：会把多个业务事件对应同一来源的语义拆散；选择人工维护映射，生成器只根据 Attribute 收集来源。
- 读取追踪/可观察存储：能自动收集依赖，但需要改造数据读写契约，本次不引入。
- Roslyn Source Generator：能随编译生成与诊断，但增加独立构建、DLL 分发及编辑期开销维护；现有菜单和构建前过期检查足够。

## 影响

- 新条件实现求值并显式声明来源；新增来源仍需补齐枚举和业务事件映射，生成器不能证明通知覆盖所有实际状态变化。
- 来源按游戏/全局及 int/bool 拆为四类，不细化到变量 ID。同条件共享缓存，最后一个观察取消时释放。
- 一批先提交全部条件结果再通知与应用，应用产生的新 dirty 延至下次 LateTick；不提供跨帧事务，也不能捕捉两次刷新间全部瞬态。
- NPC 不再依靠持续轮询补建被外部移除的 Entity；条件结果变化、配置重建或重新入场时才重新选择和补建。
- 集中处理保证固定刷新阶段，不保证固定 CPU 上限；实际性能需分别测量求值与应用成本。
- 未支持类型返回 None 表示该分支没有可登记的来源，不自动改为轮询；需要根据 Error 修正声明并重新生成。组合条件继续收集其他分支的来源。

## 后续简化（2026-11-01）

随 ActionSystem 结果回调和场景事件临时提交标记移除，不再保留分发回调的版本保护。当前状态接收方及行为不会同步清空或重建场景事件登记，SceneEvent 信任该同步生命周期契约，一并移除登记版本；以上版本保护描述仅记录原方案背景。条件观察、LateTick 批次处理和观察 Token 的生命周期契约保持有效。
