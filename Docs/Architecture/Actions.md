# ActionSystem

ActionSystem 是行为总表的统一执行入口，以同步 FIFO 分发保证当前 Action 的同步逻辑和结果回调完成后再执行重入提交的行为。

## 职责与边界

System 负责按 ActionId 查询配置、同步重入队列、执行结果反馈及异常隔离；ActionResolver 接收 ActionDef 与 ActionContext，返回 bool。持续行为的驱动、资源独占、替换、取消和清理由 SequenceSystem 等所属系统管理。

true 表示行为已成功发起或完成空操作，不表示剧情等持续行为已经结束。后续播放失败、被替换或离场取消不改变已反馈的结果，不触发回滚或自动重试。

## 主要类型与入口

`Submit(int actionId, Action<bool> onExecuted = null)` 无同步返回结果。调用方不关心结果时省略回调；已接收的提交在实际执行或清理失败后反馈一次 bool。

空闲提交立即执行，回调可能在 Submit 返回前发生。Resolver 或结果回调期间的重入提交按 FIFO 排队，最外层 Submit 在正常情况下处理完本轮全部提交后返回；不等待下一帧、不使用 UniTask、不等待持续行为结束。

## 生命周期与核心语义

System 作为常规 SystemBase 注册，在初始化时绑定 ActionContext，不持有流程帧任务。Submit 遵循架构生命周期契约，由调用方保证只在初始化完成后、Shutdown 前调用。每次实际执行查询最新配置，已经发起的行为归所属系统管理，行为表重载只影响后续执行。

缺失 ID、未知定义、同步发起失败或异常反馈 false；生成分发器保留空定义作为空操作成功的语义，调用具体 Resolver 时定义已保证非空。执行与回调异常分别记录，回调异常不改变执行结果，不阻塞下一项。

单轮最多执行 1024 个行为；超限时记录触发循环错误，未执行项反馈 false。Shutdown 将未执行项收束为 false，不撤销已发起行为。失败清理期间重入提交直接拒绝并记录错误，不再调用新提交的回调，避免失败回调无限扩展清理工作。

## 使用与扩展规则

- 配表行为统一经 Submit 发起，消费方不直接调用生成分发器绕开队列。
- 入队代表已决定执行，出队不重新判断触发条件或调用来源；提交前完成业务判断。队列只保证单个 Action 不被重入 Action 打断，不提供状态事务。
- 提交前准备好回调使用的状态。回调持有场景对象时由消费方检查登记身份和生命周期，防止更新旧对象。SceneEventSystem 每次离场、重建或关闭均递增登记版本，以挂载状态、登记版本及 Unity 对象有效性判断旧回调是否仍可更新状态。
- 多次提交相同 ActionId 是独立执行；场景事件不维护完成记录，是否可再次触发由条件和业务变量决定，提交期间仅保留临时防重入。
- 新行为沿用 DefinitionResolverAttribute 和模板生成流程，返回同步 bool，不返回执行监视器。
- 设置游戏/全局整数、布尔变量的四种行为分别调用对应 Command，未配置变量 ID 时记录 Error 并反馈 false；全局变量立即保存，文件写入失败由现有执行异常链路反馈 false，内存修改保留，见[变量模块](Variables.md)。
- 独占冲突按所属系统的语义处理；剧情沿用新播放取消旧播放。角色运动能力与 Sequence 内部 Action/Yield 的生命周期不受此接口影响。
