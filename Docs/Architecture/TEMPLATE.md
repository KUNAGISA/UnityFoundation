# 架构文档模板

架构文档只记录当前有效的框架事实：接口、职责边界、生命周期、扩展方式、约束和排错。历史取舍及原因写入 ADR；具体玩法流程、业务状态和界面操作写入对应业务资料；能直接从代码低成本确认的文件清单和实现细节不重复维护。

“职责与边界”和“使用与扩展规则”为必写章节。其余章节按主题需要保留，删除不适用的章节，不创建空章节。代码路径只用于定位稳定入口，示例只用于解释框架 API。

复制以下内容创建新文档：

```md
# <模块或主题名称>

<用一段话说明模块解决的问题、适用范围和边界。>

## 职责与边界

<说明负责什么、不负责什么，以及与相邻模块的所有权边界。>

## 主要类型与入口

<列出稳定入口、能力接口及必要的源码位置。>

## 生命周期与核心语义

<说明初始化、运行、取消、失败、释放顺序或关键数据流。>

## 使用与扩展规则

<说明调用方式、扩展点和必须保持的不变量。>

## 性能与排错

<仅在存在热路径、资源成本或常见错误时保留。>

## 验证

<列出修改该模块后应执行的可观察验证。>
```
